# improve-1-distill-feedback

資産化レイヤの1番目。試走で出た指摘を、台帳の行 → 改善 Issue の draft に変換する。これまで会話で手作業していた工程。
思想は `${CLAUDE_PLUGIN_ROOT}/DESIGN.md` の「通底する原則」(指摘はインスタンスでなく資産に還元する)。

**核**: 観測はプロダクト固有語を含めずに書く(台帳と draft は公開 repo の Issue に転記できる形)。スキル本体の diff はここでは書かない(それは PR 作業)。

## 入力契約

`${CLAUDE_PLUGIN_ROOT}/references/principles.md` に従う(出力先・書式・固有語の扱い)。

読んでよいもの(全列挙):
- 台帳(作業用メモ置き場。書式は `assets/ledger.md`)
- 対象スキルの SKILL.md / assets / `references/principles.md` / `DESIGN.md`
- 試走の成果物(作業用メモ置き場に出た要件整理・要件確認・実現案・照合結果)
- 利用者が会話で述べた指摘

読んではいけないもの:
- 対象プロダクトの repo・Issue・PR。台帳の観測は成果物と会話から書く。プロダクトの事実を調べに行かない

## 産物

| 産物 | 書式 | いつ出すか |
|---|---|---|
| 台帳の行 | `assets/ledger.md` | 指摘を受けるたび。日付 / スキル / 観測 / 提案 / 優先度 / 状態 |
| Issue draft | `assets/issue-draft.md` | 「改善 Issue にまとめて」と言われたとき。台帳の # を ID にする |
| 台帳の状態更新 | 状態列を「反映済(版)」に | 改善 PR のマージ後、利用者の指示があるときだけ |

出力先は作業用のメモ置き場。GitHub への起票・コメントは利用者の明示指示があるときだけ。

## 手順

1. **観測を 1 件ずつ切る** 利用者の指摘・成果物の差し戻し箇所を、「どのスキルの、どの手順・書式で、何が起きたか」が 1 文で言える単位に分ける。1 件に 2 つの原因が混ざっていれば 2 行にする
2. **固有語を役割語に置き換える** 観測と提案に、対象プロダクトの Issue 番号・機能名・契約者名・テーブル名・画面名・ライブラリ名を書かない。役割を表す一般語に置き換える(下の表)。固有語が無いと観測が成り立たないときは、台帳とは別の公開しないメモに書き、台帳には役割語だけ残す
   | 固有語 | 役割語の例 |
   |---|---|
   | 対象プロダクトの Issue 番号 | 「L 判定 1 件」「M 判定の子 Issue」 |
   | 具体的なマスタ名・項目名 | 「選択済みの値」「一覧に追加する項目」 |
   | 契約者名・テナント名 | 「対象機能が有効な契約者」 |
   | テーブル名・ライブラリ名 | 「保存先」「DB アクセス層」 |
3. **提案を書く** 「どのスキルの、どの手順・書式に、何を足す/外す/変える」まで。SKILL.md の文面そのものは書かない(文面は PR で決める)
4. **優先度を判定する**
   | 条件 | 優先度 |
   |---|---|
   | 同じ観測が 2 回以上出た | 高(次の版で反映) |
   | 観測が 1 件のみで再現していない | 中(試走で再現したら反映)以下 |
   | 書式の好みで品質に効かない | 低(任意) |
   既存の台帳行を上書きする提案は、提案欄の先頭に「#n を上書き」と書く
5. **台帳に追記する** `assets/ledger.md` の書式で行を足す。状態は「未着手」。# は台帳の通し番号で、振り直さない
6. **Issue draft を書く(指示があるとき)** `assets/issue-draft.md` の構成で、台帳の「未着手」行を集める。既存の DESIGN・assets と衝突する項目は「衝突」列に衝突先の節名を書き、反映後の骨格案を添える
7. **状態を更新する(マージ後・指示があるとき)** 改善 PR に含まれた # の状態を「反映済(版)」にする。含まれなかった # は「未着手」のまま残す

試走でローカルファイルを対象にする場合も、台帳は作業用ディレクトリの `ledger.md`、draft は `improve-draft.md` に書く。

## よくある失敗

- 台帳に Issue 番号・機能名・契約者名を書く → 公開 repo の Issue に転記できない。役割語に置き換え、固有語は別メモへ
- 反映済みの行を「未着手」のまま残す → 次の draft で重複する。PR マージ時に状態を更新する
- 提案を SKILL.md の文面まで書く → draft の段階では「どの手順に何を足すか」まで。文面は PR で
- プロダクトの repo を開いて観測を裏取りする → 入力契約違反。観測は成果物と会話から書く
- 1 回しか出ていない観測を「高」にする → 再現していない指摘は「中」以下。2 回目で上げる
- モデル・コストの推測を提案に書く → 計測の観測項目は DESIGN に任せる。ここでは書かない
- 「改善 Issue にまとめて」の指示で `gh issue create` まで実行する → 起票は別の明示指示。draft を提示して止まる
